# J리그1 및 API-Football 사전 배당 확장 설계

작성일: 2026-08-13  
상태: 승인됨

> 2026-08-13 최종 검증 정정: 아래 설계의 초기 `season=2026` 가정은 완료된 전환 대회를 현재 시즌으로 오인한 것이었다. 2026-27 J1의 API 시즌 키는 `2027`이며 이 정정이 원래 설계보다 우선한다.

## 1. 목표

현재 K리그1 중심의 경기 가이드에 다음 기능을 추가한다.

1. 상세경기를 열었을 때 API-Football pre-match odds를 조회해 표시한다.
2. 경기 목록에 J리그1 예정 경기를 K리그1과 함께 표시한다.
3. 순위 메뉴에서 K리그1과 J리그1을 탭으로 구분해 공식 순위를 표시한다.
4. J리그1의 API-Football 팀명과 Betman 한글 팀명을 안전하게 연결한다.

예측 저장, Betman URL 저장, 저장된 경기, 배당기록 기능의 기존 동작은 유지한다.

## 2. 확인된 외부 데이터

API-Football `/leagues?id=98`과 시즌별 일정·순위를 다시 확인한 결과, 2026-27 J리그1은 다음과 같다.

- 리그 ID: `98`
- 리그명: `J1 League`
- API 시즌 키: `2027`
- 기간: `2026-08-07`~`2027-06-06`
- 상태: `current=true`
- 일정·순위·odds coverage: 지원 (`standings=true`, `odds=true`)
- 검증 범위 `2026-08-13`~`2026-08-27`: 예정 경기 20개, 공식 standings 한 그룹 20팀

API `season=2026`은 `2026-02-06`~`2026-06-06`에 끝난 동부/서부 전환 대회이며 `odds=false`였다. 이 값은 현재 2026-27 시즌의 공급 범위를 설명하지 않는다. `season=2027`에서 coverage가 true여도 개별 경기 `/odds?fixture={fixtureId}` 결과가 비어 있을 수 있으므로 정상적인 데이터 없음 상태는 유지한다. K리그1 리그 ID는 기존과 동일한 `292`를 사용한다.

## 3. 선택한 접근 방식

리그 설정과 팀 별칭을 명시적으로 관리하는 통합 API 방식을 사용한다.

- 서버는 K리그1과 J리그1을 같은 경기 응답 계약으로 변환한다.
- Betman 연결은 리그, 날짜, 시작시간, 양 팀 별칭을 모두 사용한다.
- 문자열 유사도만으로 자동 연결하지 않는다.
- 매칭 근거가 부족하면 Betman 배당을 표시하지 않는다.

잘못된 경기의 배당을 보여주는 것보다 배당 없음 상태를 보여주는 것을 우선한다.

## 4. 서버 구조

### 4.1 리그 설정

공통 리그 설정을 한 곳에서 관리한다.

```text
K리그1: leagueId 292, leagueCode K1, timezone Asia/Seoul
J리그1: leagueId 98, leagueCode J1, timezone Asia/Tokyo
```

K리그1은 달력 연도를 시즌 키로 사용한다. J리그1은 7월~12월 날짜를 다음 연도 키로, 1월~6월 날짜를 해당 연도 키로 사용한다. J1 통계 시작은 종료 연도 전년의 7월 1일로 계산해 실제 시즌 개막을 포함한다. API 응답의 경기 시각은 화면에서 한국시간으로 통일해 표시한다.

### 4.2 경기와 순위 API

`GET /api/fixtures`는 오늘부터 14일 뒤까지 두 리그 일정을 병렬 조회하고 하나의 날짜·시간순 목록으로 반환한다. 한 리그가 실패하면 성공한 리그 결과와 리그별 오류를 함께 반환한다.

각 경기에는 다음 리그 식별자를 추가한다.

```text
leagueId, leagueCode, leagueName
leagues[].season
```

순위는 과거 경기로 앱에서 재계산하지 않고 API-Football 공식 `/standings?league={id}&season={leagueSeason}` 응답을 사용한다. 응답은 리그별로 분리하고 공급자의 단일 표 순서를 유지한다.

```text
standingsByLeague: {
  K1: Standing[],
  J1: Standing[]
}
```

표시 필드는 순위, 팀, 경기, 승, 무, 패, 득점, 실점, 득실, 승점이다.

### 4.3 pre-match odds API

새 읽기 전용 경로를 추가한다.

```text
GET /api/pre-match-odds?fixture={API-Football fixture ID}
```

동작:

1. 양의 안전한 정수 fixture ID만 허용한다.
2. API-Football `/odds?fixture={fixtureId}`를 호출한다.
3. 북메이커, 게임유형, 선택지, 배당을 화면용 계약으로 정규화한다.
4. D1에는 저장하지 않는다.
5. 동일 경기 결과는 서버 메모리에 30분 캐시한다.
6. API 응답이 비어 있으면 HTTP 200과 빈 북메이커 배열을 반환한다.
7. 외부 API 오류는 적절한 502 응답으로 구분한다.

예상 응답:

```text
{
  fixtureId,
  fetchedAt,
  cacheSeconds: 1800,
  bookmakers: [
    {
      id,
      name,
      markets: [{ id, name, values: [{ label, odds }] }]
    }
  ]
}
```

## 5. Betman과 J리그 팀 매칭

팀 ID를 기준으로 별칭 레지스트리를 만든다. 각 팀은 API-Football 영문명과 Betman 한글명을 포함할 수 있다. 비교 전에는 공백, 구두점, 대소문자, `FC` 표기 차이를 정규화한다.

매칭 조건:

1. 같은 리그여야 한다.
2. 한국시간 기준 경기 날짜가 같아야 한다.
3. 시작시간 차이가 허용 범위 15분 이내여야 한다.
4. 홈팀과 원정팀이 각각 같은 팀 ID의 별칭으로 확인돼야 한다.

리그명도 `J1 League`, `J리그`, `일본 J리그` 등 확인된 별칭으로 정규화한다. 홈·원정 양쪽이 모두 확정되지 않으면 연결하지 않는다. 매칭 실패는 사용자 화면에서 단순 배당 없음으로 처리하고, 개발 검증용 순수 함수 테스트에서 원인을 확인한다.

신규 승격·강등 또는 Betman 표기 변경 시 별칭 레지스트리만 수정하면 되도록 경기 화면 로직과 분리한다.

## 6. 화면 설계

### 6.1 경기 메뉴

- K리그1과 J리그1 경기를 구분 없이 날짜·시각순으로 표시한다.
- 각 경기 카드에 `K리그1` 또는 `J리그1` 배지를 표시한다.
- 상단 제목은 두 리그를 포함하도록 변경한다.
- 기존 Betman 회차 URL 입력은 경기 메뉴에서 그대로 한 번만 제공한다.

### 6.2 상세경기

기존 상세 정보와 Betman 배당을 유지하고 별도의 `API-Football 사전 배당` 영역을 추가한다.

- 상세경기를 선택할 때만 pre-match odds를 호출한다.
- 북메이커 선택 상자로 반환된 북메이커를 전환한다.
- 선택한 북메이커의 게임유형과 선택지별 배당을 표 형태로 표시한다.
- 로딩, 데이터 없음, API 오류 상태를 각각 표시한다.
- 다른 상세경기로 이동하면 이전 요청 결과를 재사용하지 않는다.
- API-Football 배당은 참고 정보이며 확률 입력 및 저장 대상이 아니다.

### 6.3 순위 메뉴

- `K리그1`, `J리그1` 탭을 제공한다.
- 기본 탭은 K리그1이다.
- 각 탭은 해당 리그의 공식 순위표와 독립된 로딩·오류·빈 상태를 표시한다.

## 7. 호출 및 캐시 정책

- 경기·순위: 첫 화면 진입 시 두 리그를 병렬 조회한다.
- 경기·순위 서버 캐시: 기존 10분 정책을 유지한다.
- Predictions: 기존처럼 상세경기 선택 시 호출하고 10분 캐시한다.
- pre-match odds: 상세경기 선택 시 호출하고 30분 캐시한다.
- Betman: 사용자가 저장한 회차 URL을 사용하며 기존 10분 캐시를 유지한다.
- 자동 폴링이나 백그라운드 수집은 추가하지 않는다.

## 8. 오류 처리

- K리그 또는 J리그 중 하나만 실패하면 성공한 리그는 계속 표시한다.
- 경기 목록 위에 `role=status` 부분 실패 경고를 표시해 공급자 실패를 예정 경기 0개와 구분한다.
- 두 리그 모두 실패했을 때만 경기 전체 오류 화면을 표시한다.
- 순위 탭 오류는 다른 리그 탭에 영향을 주지 않는다.
- pre-match odds 빈 응답은 `제공되는 사전 배당이 없습니다`로 표시한다.
- Betman 팀 매칭 실패는 API-Football 배당이나 기본 경기 상세 표시를 막지 않는다.

## 9. 테스트와 완료 조건

단위 테스트:

- K1/J1 리그 설정과 응답 정규화
- K1 달력 연도 및 J1 종료 연도 시즌 해석과 J1 통계 시작일
- 두 리그 경기 병합 및 날짜·시간 정렬
- 리그별 순위 변환
- 현재 J1 `season=2027`의 공식 단일 20팀 순위와 고유 rank/team ID
- pre-match odds 정상·빈 응답·잘못된 fixture ID
- J리그 영문명과 Betman 한글명 매칭
- 모호하거나 불완전한 팀 별칭의 오매칭 방지

통합·회귀 검증:

- 경기 목록에서 두 리그 배지 확인
- 상세 선택 시에만 pre-match odds 요청
- 북메이커 전환과 빈 상태 확인
- 순위 탭 전환 확인
- 기존 Betman 저장, 확률 저장, 저장된 경기 조회·삭제 유지
- 타입 검사, 린트, 빌드, 전체 테스트, 읽기 전용 하네스 통과
