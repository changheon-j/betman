# 경기 목록·상세분석 작업공간 및 전체 북메이커 표시 설계

## 목표

경기 메뉴의 첫 화면은 예정경기 탐색에 집중하고, 사용자가 경기를 선택한 경우에만 상세분석 작업공간으로 전환한다. 상세분석이 열린 데스크톱 화면에서는 경기 목록과 상세분석이 각자 스크롤되며, API-Football 사전배당은 북메이커 선택 없이 모든 업체의 Match Winner 배당을 한 번에 표시한다.

## 화면 상태

경기 메뉴는 다음 두 상태만 사용한다.

### 목록 상태

- 최초 접속 시 기본 상태다.
- 예정경기 목록이 콘텐츠 영역 전체 폭을 사용한다.
- 첫 번째 경기를 자동 선택하지 않는다.
- 상세분석 패널을 렌더링하지 않는다.
- 선택 경기가 없으므로 Predictions와 API-Football 사전배당을 호출하지 않는다.
- Betman 회차 URL 입력과 예정경기 필터는 현재 위치와 기능을 유지한다.

### 상세 상태

- 사용자가 경기 카드 또는 `분석 보기`를 선택하면 진입한다.
- 데스크톱에서는 왼쪽 예정경기 목록과 오른쪽 상세분석을 반반 화면으로 표시한다.
- 선택한 경기 카드의 강조 표시는 유지한다.
- 오른쪽 상세분석 최상단 우측에 `×` 닫기 버튼을 둔다.
- 닫기 버튼에는 `상세분석 닫기` 접근성 이름을 제공한다.
- 닫으면 선택 경기 ID를 해제하고 목록 상태로 돌아간다.
- 닫은 뒤 다시 경기를 선택하면 해당 경기의 상세분석을 처음부터 표시한다.

## 데이터 흐름

- `selectedId`의 초기값은 선택 없음 상태를 나타내는 값으로 둔다.
- 경기 API 응답을 받은 뒤에도 첫 경기 ID를 자동으로 저장하지 않는다.
- `selected`는 실제 `selectedId`와 일치하는 경기만 반환하며 첫 경기 fallback을 사용하지 않는다.
- 경기 선택 시에만 기존 Predictions와 API-Football 사전배당 효과가 실행된다.
- 상세 닫기 또는 다른 경기 선택 시 기존 취소 가드를 이용해 이전 경기의 늦은 응답이 화면에 나타나지 않도록 한다.
- 상세 닫기 시 선택 경기 전용 오류·로딩·북메이커 표시 상태는 화면에서 즉시 제거된다.
- Betman 회차 자체 조회는 경기 메뉴의 공통 설정이므로 기존과 같이 메뉴 진입 시 수행한다.

## 데스크톱 레이아웃과 스크롤

- 상세 상태일 때 콘텐츠 작업공간의 사용 가능한 화면 높이를 기준으로 왼쪽과 오른쪽 패널의 최대 높이를 정한다.
- 왼쪽 경기 목록과 오른쪽 상세분석에 각각 세로 스크롤 컨테이너를 둔다.
- 마우스 포인터가 왼쪽 영역에 있으면 경기 목록만, 오른쪽 영역에 있으면 상세분석만 스크롤된다.
- 경기 선택 직후 오른쪽 상세분석 컨테이너에 프로그램 방식으로 포커스를 이동한다. 포커스 이동을 위해 컨테이너는 키보드 탐색 가능한 요소가 되지만 불필요한 시각적 테두리는 표시하지 않는다.
- 상세 패널의 기존 `sticky` 동작은 독립 스크롤 작업공간과 중복되므로 상세 상태에서는 사용하지 않는다.
- 목록 상태에서는 전체 폭의 일반 페이지 흐름을 사용하고 별도의 내부 스크롤을 강제하지 않는다.

## 작은 화면 동작

- 기존 단일 열 전환 기준인 1050px 이하를 작은 화면으로 사용한다.
- 목록 상태에서는 예정경기 목록을 전체 폭으로 표시한다.
- 상세 상태에서는 예정경기 목록을 숨기고 상세분석만 전체 폭으로 표시한다.
- 상세 닫기 버튼을 누르면 목록 상태로 돌아간다.
- 상세 상태로 전환하면 상세 패널 시작 위치로 이동해 사용자가 선택한 결과를 즉시 볼 수 있게 한다.
- 모바일 하단 메뉴와 다른 대메뉴의 동작은 변경하지 않는다.

## API-Football 전체 북메이커 배당

- 북메이커 `<select>`와 선택 북메이커 상태를 제거한다.
- API가 반환한 북메이커를 응답 순서대로 모두 표시한다.
- 각 북메이커는 한 행으로 표시하며 열은 `북메이커`, `Home / Draw / Away`다.
- 완전한 Match Winner가 있으면 Home, Draw, Away 순서로 소수점 둘째 자리까지 표시한다.
- 예시: `4.10 / 3.35 / 1.90`
- Match Winner가 없거나 세 값 중 하나라도 없으면 해당 북메이커 행에 `미제공`을 표시한다.
- 일부 업체가 미제공이어도 다른 업체의 행은 정상 표시한다.
- 북메이커 배열 자체가 비어 있으면 기존 `현재 제공된 사전 배당이 없습니다.` 상태를 유지한다.
- API 호출 실패와 로딩 상태도 기존 안내를 유지한다.
- `/api/pre-match-odds` 응답 계약, 30분 캐시, API 호출 방식과 DB 비저장 정책은 변경하지 않는다.

## 구성 요소 경계

- 경기 선택 여부와 화면 모드를 계산하는 로직은 테스트 가능한 작은 함수 또는 컴포넌트로 분리한다.
- 상세 패널 머리글과 닫기 버튼은 상세분석 영역의 책임으로 둔다.
- 전체 북메이커 Match Winner 표시는 기존 `matchWinnerOdds` 순수 함수를 재사용하는 전용 컴포넌트로 분리한다.
- `app/page.tsx`는 데이터 상태와 화면 전환을 조정하고, 배당 행의 세부 출력 로직을 직접 반복하지 않는다.
- 기존 Betman 배당, 확률 입력·저장, Predictions, 최근 흐름, 순위와 맞대결 구성은 변경하지 않는다.

## 접근성

- 닫기 버튼은 실제 `<button type="button">` 요소를 사용한다.
- 닫기 버튼의 시각 문자는 `×`, 접근성 이름은 `상세분석 닫기`다.
- 상세 선택 후 포커스는 오른쪽 상세 컨테이너로 이동한다.
- 닫은 후 포커스는 가능하면 방금 선택했던 경기의 `분석 보기` 버튼으로 복귀한다.
- 전체 북메이커 배당은 표 구조와 열 머리글을 사용해 업체명과 1X2 배당 관계를 전달한다.
- `미제공`은 색상에만 의존하지 않고 텍스트로 표시한다.

## 오류 및 경계 처리

- 경기 목록이 비었으면 기존 빈 목록 상태를 유지하고 상세 상태로 진입하지 않는다.
- 선택한 경기 ID가 새로운 경기 응답에 존재하지 않으면 선택을 해제해 목록 상태로 돌아간다.
- 상세를 빠르게 열고 닫거나 다른 경기를 선택해도 이전 Predictions·사전배당 응답이 현재 상세에 노출되지 않아야 한다.
- 북메이커별 중복·잘못된 배당 제거는 기존 서버 정규화 계약을 그대로 사용한다.

## 테스트

- 경기 응답 후 자동 선택이 발생하지 않는지 검증한다.
- 목록 상태에서 상세 패널이 없고 경기 목록이 전체 폭 모드인지 검증한다.
- 경기 선택 시 상세 상태와 선택 경기 데이터가 나타나는지 검증한다.
- `×` 닫기 버튼이 선택을 해제하고 목록 상태로 복귀시키는지 검증한다.
- 상세 선택과 닫기 시 API 호출 조건 및 이전 응답 차단 규칙을 검증한다.
- 모든 북메이커가 하나의 표에 표시되는지 검증한다.
- 완전한 업체는 `4.10 / 3.35 / 1.90`, 불완전한 업체는 `미제공`인지 검증한다.
- 북메이커 선택상자가 제거됐는지 검증한다.
- 데스크톱 독립 스크롤 클래스와 작은 화면 목록·상세 전환을 검증한다.
- 전체 타입 검사, 린트, 빌드, 단위 테스트와 렌더링 테스트를 실행한다.
