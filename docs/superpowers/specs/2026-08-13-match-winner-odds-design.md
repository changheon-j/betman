# API-Football Match Winner 배당 표시 설계

## 목표

상세 경기의 API-Football 사전 배당 영역에서 사용자가 북메이커를 선택하면 `Match Winner` 마켓만 간결하게 표시한다. 기존처럼 선택지마다 여러 행을 만들지 않고 Home, Draw, Away 배당을 한 행에 고정된 순서로 보여준다.

## 화면 동작

- 북메이커 선택 기능은 유지한다.
- 선택한 북메이커의 마켓 중 이름이 `Match Winner`인 항목만 표시한다.
- 다른 마켓은 화면에 표시하지 않는다.
- 표시 열은 `마켓`, `Home / Draw / Away` 두 개로 단순화한다.
- 배당은 Home, Draw, Away 순서로 소수점 둘째 자리까지 한 행에 표시한다.
- 예시: `4.10 / 3.35 / 1.90`
- 선택한 북메이커에 `Match Winner`가 없거나 Home, Draw, Away 중 하나라도 없으면 잘못 조합하지 않고 `Match Winner 배당이 제공되지 않습니다.`라는 안내를 표시한다.
- 북메이커 변경 시 선택된 북메이커의 값으로 즉시 갱신한다.

## 데이터 처리

API 응답과 `/api/pre-match-odds` 계약은 변경하지 않는다. 화면에서 선택된 북메이커의 정규화된 `markets` 배열을 읽고 다음 규칙을 적용한다.

1. 마켓 이름을 공백 제거와 소문자 변환 후 `matchwinner`와 비교한다.
2. 선택지 이름을 같은 방식으로 정규화해 Home, Draw, Away를 찾는다.
3. 세 선택지가 모두 있을 때만 Home / Draw / Away 순서의 표시 문자열을 만든다.
4. 중복 마켓이나 중복 선택지가 있으면 정규화 모듈이 유지한 첫 번째 유효 값을 사용한다.

화면 전용 선택 로직은 순수 함수로 분리해 테스트할 수 있게 한다. DB 저장과 Betman 확률 입력 기능에는 영향을 주지 않는다.

## 오류 및 빈 상태

- API 호출 실패와 북메이커 전체 미제공 상태는 기존 안내를 유지한다.
- 북메이커는 있으나 `Match Winner`만 없는 상태는 별도 안내로 구분한다.
- 일부 선택지만 존재하는 불완전한 마켓은 표시하지 않는다.

## 테스트

- 순서가 섞인 Home, Draw, Away를 고정 순서로 반환하는지 검증한다.
- 대소문자와 공백 차이를 허용하는지 검증한다.
- 다른 마켓을 제외하는지 검증한다.
- 선택지가 하나라도 누락되면 빈 결과를 반환하는지 검증한다.
- 렌더링 결과가 한 행과 `Home / Draw / Away` 형식으로 표시되는지 확인한다.

## 서브에이전트 표기 원칙

- 시스템 내부 작업 식별자는 플랫폼 제약상 영문 소문자와 숫자, 밑줄을 사용할 수 있다.
- 사용자에게 진행 상황을 설명할 때 내부 식별자는 노출하지 않는다.
- 사용자에게는 `화면개발 담당 — 사전배당 UI 수정`, `테스트 담당 — 회귀 테스트 검증`처럼 한글 역할명과 현재 용도를 함께 표시한다.
- 이후 모든 서브에이전트 관련 중간 보고와 완료 보고에 이 원칙을 적용한다.

## 범위 제외

- API-Football 호출 주기 및 캐시 정책 변경
- 사전 배당 DB 저장
- Betman 배당 화면 변경
- Match Winner 외 마켓을 선택하는 추가 필터
